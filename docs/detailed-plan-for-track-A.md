# Track A 详细实施计划

本文档面向 A 线工程师。A 线主责是 **路线构造与空间优化**：在统一路网和统一路线方案契约基础上，生成固定组数、任意组数和代表性参数下的候选巡视路线。

A 线开工前必须先确认项目已经采用的共享标准。当前 B 线已经先行完成公共路网底基，相关标准不是 B 线私有实现，而是 A/B 两线共同遵守的最终统一标准。

---

## 0. 开工前必须确认

### 0.1 Git 分支

建议从最新 `main` 开短生命周期分支：

```powershell
git switch main
git pull
git switch -c a/route-builder-bootstrap
```

A 线功能分支命名使用 `a/...`。如果工作中需要修改路网读取、节点分类、路线方案契约、公共数据结构或公共测试夹具，不要直接夹带在 `a/...` 分支中，应先开 `shared/...` 分支处理。

### 0.2 必须遵守的共享路网标准

A 线必须使用 `mm_final.network` 作为路网公共入口：

- 使用 `load_road_network()` 读取正式路网。
- 使用 `RoadNetwork` 表达道路网络，不直接维护另一套邻接表作为公共语义。
- 使用 `NodeType` 和 `classify_node()` 识别节点类型。
- 使用 `TOWN_NODES`、`VILLAGE_NODES`、`AUXILIARY_NODES`、`REQUIRED_VISIT_NODES` 等共享常量。

节点语义必须与 B 线审计保持一致：

- `O` 是县政府所在地和 depot，不是乡镇，不产生乡镇停留时间。
- `A`–`R` 中除 `O` 外的大写字母是乡镇节点。
- `1`–`35` 是村节点。
- `U01`–`U05` 是辅助道路节点，只能作为通行点，不能作为必访停留点。
- 道路网络是无向加权图，边权单位为 km。

### 0.3 必须遵守的路线方案契约

A 线所有正式候选方案必须输出 `RoutePlan` 契约格式，详见 `docs/contracts/route-plan-contract.md`。

特别注意：

- `required_visit_order` 只写真正需要巡视和停留的乡镇/村节点。
- `required_visit_order` 不写 `O`，也不写 `U01`–`U05`。
- 实际通行路径如果展开，应写入 `expanded_node_path`，且首尾必须是 `O`。
- 暂未计算的 nullable 字段保留字段名并写为 `null`，不得省略字段。

## 1. A0：开工计划细化

### 目标

在正式写路线构造算法前，先细化 A 线自己的执行计划，避免与共享底基或 B 线审计口径冲突。

### 建议输出

- A 线阶段计划。
- A1 路网使用测试计划。
- A2 单路线构造器测试计划。
- A/B 握手点清单。
- 需要 B 线提前提供的审计输入或样例。

### 验收标准

- 计划明确哪些内容属于 A 线私有算法，哪些内容属于共享底基。
- 不重复实现 `mm_final.network` 已有能力。
- 不绕过 `RoutePlan` 契约。

## 2. A1：路网与最短路基础

### 目标

基于 `mm_final.network` 建立路线构造所需的路网访问能力，并实现或对接最短路查询。

### 约束

- 路网读取和节点分类必须复用 `mm_final.network`。
- 如果需要新增最短路公共接口，应优先走 `shared/...` 分支，避免 A/B 各自维护最短路口径。
- 最短路距离单位为 km，实际路径允许包含辅助道路节点。

## 3. A2：单路线构造器

### 目标

给定一组必访节点，生成一条从 `O` 出发并返回 `O` 的闭合路线。

### 建议方法

- 最近邻基线。
- 最便宜插入。
- 路线内 2-opt。
- 多起点重启。

### 验收标准

- 输入必访点全部覆盖。
- 辅助道路节点不进入 `required_visit_order`。
- 输出可转换为 `RoutePlan`。

## 4. A3：固定 3 组路线优化

### 目标

主攻第 (1) 问：固定 3 组时，在总路程尽量短的前提下保持各组均衡。

### 验收标准

- 输出 3 条闭合路线。
- 所有乡镇和村节点恰好分配一次。
- 结果可交给 B 线审计器读取和复核。

## 5. A4：任意组数与方案池

### 目标

支持 `k=1,2,3,...` 的路线生成，为第 (2)(3) 问提供候选方案池。

### 验收标准

- 每个候选方案都有 `plan_id`、`source`、`parameters`、随机种子和运行耗时记录。
- 候选方案统一输出 `RoutePlan`。
- 对不可行或低质量方案，不在 A 线内部直接做最终结论，应交给 B 线审计和下界分析。

## 6. A5：路线改进与最终候选

### 目标

通过组间迁移、交换、路线内局部搜索和多候选保留提升路线质量。

### 验收标准

- 对同一问题能提供多套候选。
- 候选方案可被 B 线按合法性、耗时、均衡性和瓶颈路线排序。
- 最终报告中的路线结构和算法说明与 B 线审计结果一致。
