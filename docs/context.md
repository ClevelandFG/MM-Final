# 上下文说明

本文档用于记录Agent与用户达成的共识、约定俗成的术语等内容。

---

## 术语表

- **道路网络**：由题面给出的无向加权图构成，节点表示乡镇、村或辅助道路点，边权表示对应路段的千米数。
- **县政府所在地**：节点 `O`，所有巡视路线均从该节点出发并最终返回该节点。
- **乡（镇）节点**：`A`–`R` 中除 `O` 外的大写字母表示的必须巡视节点；在计时问题中每个乡（镇）停留时间记为 `T`。
- **村节点**：数字 `1`–`35` 表示的必须巡视节点；在计时问题中每个村停留时间记为 `t`。
- **辅助道路节点**：`U01`–`U05`，为保留题面道路权重而人工添加，只作为路径连接点，不计入必须巡视点，也不产生停留时间。
- **巡视路线**：一组巡视人员从 `O` 出发，访问分配给该组的必须巡视节点，并返回 `O` 的闭合路线。
- **路线组**：同一方案中若干条巡视路线的集合；组数即同时派出的巡视队数量。
- **路线方案**：由一条或多条巡视路线组成的完整候选方案，用于回答固定组数、最少组数或最短完成时间等问题。
- **候选方案池**：A 线或手工流程为一个或多个组数 `k` 提供的多套路线方案集合；B5 第一版把它视为按 `k` 归组的 `RoutePlan` 集合，不额外要求 candidate-pool JSON envelope。
- **可行性审计**：对路线方案是否可用于结果讨论的合法性判断，重点区分字段、覆盖、路径和指标四类问题；不承担组数下界或不可能性证明。
- **审计模式**：B3 可行性审计的运行口径，第一版区分 `candidate` 与 `final`；前者服务中间候选方案修复，后者服务正式结果讨论。
- **候选审计**：面向 A 线中间候选方案的宽松审计，用于定位需要修复的问题，不等同于最终结果合法性证明。
- **最终审计**：面向报告和结论使用的严格审计；只有通过最终审计的路线方案才能作为结果讨论依据。
- **下界**：对某个组数或完成时间不可能低于某值的数学约束；下界不构造路线，只用于解释不可能性、筛查候选组数或与候选方案上界合成证明。
- **强排除**：由严格数学成立的下界推出某个组数或完成时间目标不可能达成；启发式或筛查性弱下界不能用于强排除。
- **上下界差距**：B 线下界与 A 线候选方案上界之间的差值；差距为 0 或在容差内合拢时，才能形成强最优结论。
- **候选预筛**：候选池很大时，用 B2/共享评分核心对候选方案做快速排序或抽样的加速步骤；预筛只决定审计顺序或进入终审的批量，不产生最终合法性或最少组数结论。
- **单点一组基线**：人员足够时，为每个必须巡视节点单独安排一条从 `O` 出发并返回 `O` 的巡视路线；它用于给第 (3) 问提供可构造上界，并和单点往返下界合成最短完成时间证明。
- **等最短时间候选**：完成时间在最短完成时间下界容差内的合法路线方案；它可以在不牺牲最短完成时间的前提下比较组数、总路程和均衡性。
- **总路程**：一个路线组内所有巡视路线行驶里程之和。
- **完成时间**：一个路线组内耗时最长路线的总耗时；单条路线总耗时由行驶时间与节点停留时间共同决定。
- **均衡性**：多条巡视路线在选定“工作负载”上的接近程度。工作负载可以是路线距离、总耗时、服务节点数或服务量；本项目第 (1) 问优先按路线距离理解均衡，第 (2)–(4) 问优先按总耗时和瓶颈路线理解均衡。
- **参数敏感性**：固定或改变组数时，乡镇停留时间 `T`、村停留时间 `t`、车速 `v` 的变化对最佳路线结构与目标值的影响。
